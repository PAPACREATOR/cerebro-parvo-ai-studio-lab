# Contribuir

Contribuições são bem-vindas, sobretudo testes adversariais, documentação, revisão de arquitetura, integrações pequenas e reprodução de bugs.

## Antes de programar

1. Procure uma issue existente.
2. Explique o problema e o comportamento esperado.
3. Prefira `usar > adaptar > criar`.
4. Não introduza uma nova dependência quando Piece/MCP/API/CLI já resolve a função.
5. Preserve as invariantes: autoridade humana, Creative/Canonical, 3 memórias, 3 comparadores, proveniência, genealogia e IA sem autoridade.

## Pull requests

Um PR deve:

- ser pequeno e focado;
- ter testes positivos, negativos e adversariais quando aplicável;
- declarar dependências/licenças novas;
- não conter segredos nem dados pessoais;
- explicar em linguagem natural o comportamento do flow/regra;
- não marcar NOT RUN/SKIP como PASS.

Código de terceiros não deve ser copiado sem origem, commit/versão e licença.

## Licenciamento das contribuições

O projeto usa PolyForm Noncommercial 1.0.0 para a distribuição comunitária e pretende manter a possibilidade de licenciamento comercial separado.

Por isso, PRs com código ou documentação original só devem ser fundidos quando o contribuidor aceitar o [Contributor License Agreement](CONTRIBUTOR_LICENSE_AGREEMENT.md). O contribuidor mantém o copyright; o acordo concede ao mantenedor os direitos necessários para distribuir e relicenciar a contribuição, incluindo em ofertas comerciais.

A aceitação é registada pelo checkbox correspondente no template do pull request. Para contribuições de empresas ou situações de propriedade intelectual complexa, pode ser necessário um acordo separado.

## O que não prometemos

Contribuir não cria automaticamente emprego, participação societária, royalties ou direito a receitas. Qualquer relação comercial ou remuneração exige acordo escrito separado.
