# F002 — contratos, leis, Creative e gate

INPUT: JSON de pedido/resultado, conteúdo candidato, decisão explícita.
OUTPUT: candidato Markdown com proveniência; Canonical apenas após decisão vinculada.
LEIS: autoridade humana, separação, sem eliminação, UNKNOWN preservado.
DEPENDÊNCIAS: jsonschema existente; approval_binding do núcleo; biblioteca padrão.
TESTES prévios: JSON duplicado/inválido/NaN e schema errado; leis divergentes; input vazio; resultado vazio; promoção sem decisão; hash alterado; destino incorreto; repetição; reinício após RUNNING; sem eliminação por similaridade.

O diretório Canonical é criado numa operação de rename de um pacote completo com conteúdo, decisão e proveniência. A aprovação da aplicação é uma decisão explícita numa sessão local, não autenticação biométrica nem sandbox contra processos da mesma conta.
